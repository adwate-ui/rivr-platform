# 0620. The buy-in trigger removed from promotions

Issue #1009; the owner, 15 Nov: "Remove it". Nothing records a buy-in since the cage went (decision 0587), so the trigger never fired. Decided while building:

- **What went.** The reward kinds `buyin_bonus` (percent or fixed) and bonus chips on `first_buyin`, the event kind `buy_in`, the old engine's `buy_in` rule trigger, the "Buy-in bonus Tuesday" template (`tuesday_bonus`) and the builder's quiet conversion of an old buy-in reward to a seat bonus. `@rivr/domain` and `private.promo_grant` no longer name the refusals `nothing_earned` and `not_first_buy_in`: chips are whole 50s from 50, so a grant of nothing cannot be reached.
- **"Ended" is "removed whole".** A promotion that only a buy-in set off is deleted with its versions, rules and budget, as the free spin's and the points multiplier's were (20261115110000, 20261116200000): a version's reward must stay one the schema accepts, so an ended row cannot keep a buy-in reward. The migration prints how many went, by status (`Buy-in promotions removed, by status: ...`).
- **The template goes whatever its version became.** On 10 Nov the seat bonus migration (20261110130000) turned a buy-in draft into a seat bonus draft. Where the Buy-in bonus Tuesday template still has that one version, untouched by anyone, with its `buy_in` rule and no grant, it goes whole: the owner's word is that the template goes. Read on 15 Nov: production has exactly that, in the practice venue; staging has the template paused at each venue with a buy-in bonus. All three go.
- **It stops instead of guessing** for what a person must decide: a buy-in promotion that ever gave a grant (a member's history, which counts against limits); one with a rule of another trigger; and one with a version of another kind that is live or scheduled, that someone wrote, changed, submitted or decided, that is a second version, or that belongs to a promotion that is not the template.
- **Golden cases.** The fourteen cases of the buy-in's own sums are deleted from `promotionRewards.json`; the cases that only used a buy-in to carry eligibility, limits, period keys or the tally now carry them on a seat or a visit. Database tests moved the same way; `084` runs the old engine on `hand_logged`, a trigger nothing fires, because every seat's visit fires `check_in`.
- **The seed** runs the referral alone. Seeded Bonus history lines that named the Tuesday bonus now name the referral.
- **Left, as follow-ups.** The old rule engine's share-of-an-amount bonus (`percent_bps`, `promotionReward`, `private.promotion_reward`, and `amount_paise` with `method` in `evaluate_promotions`): no event carries an amount now, so it cannot pay, but it is a rule of the old engine, not of the trigger, and goes with that engine. Test fixtures and stories that only use "Buy-in bonus Tuesday" as a name are unchanged.
