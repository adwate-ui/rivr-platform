# 0673 Error reports from every web app, through one package

Date: 16 Nov 2026. The owner, 16 Nov: "Complete the sentry implementation" (#1004): after the player (decision 0672), the console, the dealer tablet, the TVs and the website; no Edge Functions; reports go straight to Sentry. Scrubbing, what is sent and what never is stay as decision 0604 has them.

- **One package.** The player's module moved to `@rivr/error-reporting` unchanged in what it does, made a factory: `createErrorReporting({ dsn, app, version, environment, scriptsAt })`. Decision 0604's exception now reads: the apps post to Sentry from this package and nowhere else. Source maps come from `@rivr/config/sentry` (`sentrySourceMaps(project, { mapsIn })`, `uploadsSourceMaps`), which also turns off the Sentry CLI's telemetry. The website makes and uploads the maps of its browser scripts only (`dist/client`); its Worker keeps its own as before, which Wrangler sends to Cloudflare (#1029).
- **A Sentry project per app** (`rivr-console`, `rivr-tablet`, `rivr-display`, `rivr-web`), each with a production key (100 reports an hour) and a staging key (30), and Allowed Domains of its own deploys only: `console.rivrpoker.com`, `tablet.rivrpoker.com`, `tv.rivrpoker.com`, `rivrpoker.com` and `www.rivrpoker.com`, and each one's staging address. The keys are the variables `SENTRY_DSN_CONSOLE`, `_TABLET`, `_DISPLAY` and `_WEB` of each GitHub environment, passed as `VITE_SENTRY_DSN_<APP>` (the website: `PUBLIC_SENTRY_DSN_WEB`, with `PUBLIC_SENTRY_ENVIRONMENT` and `PUBLIC_APP_VERSION`, Astro's names).
- **What each reports:** errors nothing caught, a screen that failed to draw (the router's `defaultOnCatch`), and every read that fails or change refused (`RivrDataProvider`'s `onFailure`), by short code. The console's desk camera also reports a camera that would not start or a photo that could not be made (`camera:*`), and now tells staff so. The website reports errors in its pages' scripts only, never its server rendering (a Worker, as Edge Functions are left out). Astro inlines a script under 4 KB into the page, where its errors would carry the page's address and be dropped, so the website's build keeps every script a file under `/_astro/` (`assetsInlineLimit`). Each website report is labelled with the page's route pattern (`/[slug]`), which the server writes on the page, never its address: a mistyped link can fill that with a number.
- **The practice venue never reports.** The console: the venue the staff member works in now, which they can switch to the practice one (`useStaffVenue`); signed out or no venue's staff, errors are sent; while it is read, they wait. The tablet: the venue it is paired to (`useMyDevice`). The TVs: `my_tv_screen` now returns `is_practice` (migration `20261122120000_tv_screen_says_practice.sql`, its last column, so a TV on the build before reads as it did), and anything but a plain no reads as the practice venue. The website: its public pages are a club's alone; the server marks a preview of an unpublished page, which reports nothing. Breadcrumbs (requests, screens) are kept only while the venue is known not to be the practice one, so a staff member who switches back to the club carries none into the club's first report. What remains, for every app as for the player (decision 0604): an error before the app knows its venue is sent, as the venue is taken to be the club until then; it carries the error alone. And a practice venue read or change that fails just after staff switch back to the club is sent as the club's, by its short code only.
- **The privacy notice** says Sentry gets a report when one of RIVR's apps or this website hits an error (migration `20261122130000_website_privacy_sentry_for_every_app.sql`).
- **What no rule can tell** (decision 0604) applies to every app: a name in an error's own words would pass. The console shows names, phone numbers, PANs and ID photos; what it reports is the same scrubbed error, never a screen's text or a photo.
