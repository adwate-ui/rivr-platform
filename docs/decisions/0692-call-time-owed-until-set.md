# 0692 Call time is owed until one is set and has run out

Date: 19 Nov 2026. Issue #1076. The owner, 18 Nov: players who set a call time get Extend call time; the floor's Add time becomes Add call time, synced with the app, and the floor is told when a player sets or extends; at zero without a call time set the player is in the leave-early bucket (Let go before call time); at zero after setting one, call time is met (regular leave).

- **One rule** for the member's Set and Extend and the floor's Add call time (`callTimeChoiceEnd`, SQL twin `private.call_time_choice_end`). Until set, a length counts from now and is open only when it ends strictly after the call time the seat started with (the owner's answer: Set call time shows once at least one length would). Once set, a length extends it from its end (from now once it has run out). The floor's Add call time counts as setting it.
- **The call time the seat started with** is the least value any change to it replaced (`private.initial_call_time`); each change only adds, so no new column is kept.
- **Owing** (`private.owes_call_time`): a seat with call time owes it until a call time has been set and has run out. One never set is owed even once the countdown reaches nought: the floor's Leave shows Let go before call time, the member's own Leave puts them on the Leaving list owing, and the door asks for it. A let-go with nought seconds short by the clock is kept (the shortfall may now be nought). Seats with no call time are unchanged.
- **The floor is told** of a member's set or extension on any screen: a toast with when they leave (one per read, never for the floor's own change or an Undo), and the rail's chime (`callTimeSet`, a one-minute count, chime only: not in the tab's count). Each seat shows "Leaves HH:MM" once set; with none set, the countdown until nought, then "Call time not set". The dealer's tablet picks Call time met only when nothing is owed.
- **The member is told** their call time is done only once one set has run out. The completion is still stamped for promotions and its event still goes (`is_set` false), so the lock screen's countdown stops. A visit let go before call time shows Left early, not Call time met.
- **Undo**: the floor undoes its own Add call time, never a member's own set, and never on a staff member's own record.
- **The member asking the floor for more time goes**: `request_call_time`, `decide_call_time_request`, the Requests list's time asks and the Time requests count. Any still waiting were declined by the migration.
- **At release**: seats the floor had added time to, or whose call time had already run out, count as set; a seat already left, in a visit still open, keeps the old rule (met at nought). Release outside club hours: consoles and apps open across it read the dropped time-ask columns until reloaded.
- **Promotions** keep counting time played as before: the call time's completion stamps are untouched.
