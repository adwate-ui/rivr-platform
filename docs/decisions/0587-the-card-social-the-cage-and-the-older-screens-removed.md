# 0587. The card, Social, the kill switch, the cage and the older screens removed

Issues #948, #950 to #954, with #995; the owner's redesign brief of 15 Nov and answers to #933, #937 and #938 (remove it all, from the backend too; cage, marker and TDS tables as well). Decided while building:

- **One migration, generated.** `20261117210000_card_social_cage_and_older_screens_removed.sql` drops 52 tables and about 490 functions and rewrites 38 that stay. It was written by a script from a database at main: a function goes when nothing kept reaches it, and a kept function is cut only where it read something gone. It refuses to run where a real cage transaction, a TDS row or a decided withdrawal exists.
- **The old console Tournaments module goes with the cage**, with its client code and the functions only it called: it sold entries through the cage. The tournament tables, tournament interest and the rules in `@rivr/domain/tournament` stay for issue 969.
- **Enum values stay, check constraints close them.** Postgres drops an enum value only by making the type again under every policy and index. `tv_mode` (jackpot, tournament clock, social wall), `device_kind` (`door`) and the site block kinds are refused by constraints instead; the four enum types nothing uses are dropped.
- **Activity has a permission of its own**, `activity.read`, super admin only, where it used the kill switch's.
- **The freeze checks stay, unused** (#937): `control_state` and `assert_writable` are untouched; nothing can engage a control now.
- **Kept because something kept still reads it:** permissions `cage.transact`, `cage.second_approve`, `treasury.manage`, `sops.manage`, `aml.review`, `dashboards.read`, `audit.read`, `hands.log`, `host_queue.manage`, `ledger.read`, `tiers.manage`; settings `credit.config`, `cage.second_approver_threshold`, `cage.cash_buy_in_limit`, `jackpot.payout`, `jackpot.drop`, `jackpot.shares`, `tds.config`, `gst.config`, `dealer.variance_threshold`, `reports.unclaimed_days`; hand logging; the tier matrix functions. Each is a follow-up once its reader goes.
- **Three money rules keep their TypeScript twin** because their SQL stays: `splitDrop`, `downVariance`, `cashLimitHit`. Their golden files are trimmed to those operations; eleven golden files of removed rules are deleted.
- **Storage buckets** `winner-cards`, `social-media` and `expense-receipts` are left, with no policy: nobody reads or writes them.
- **The player's tabs are Home, Sessions, Bonus, Profile.** Profile shows the member number, which the door now finds a member by; check-in takes a name, mobile or member number.
- **Staff networks and enrolled computers are off for every venue** (`on_staff_network` and `enforces_computers` answer false); the allowlist column is dropped. `.claude/rules/security.md` still names an allowlisted IP for the cage and admin: left for the owner to reword.
- **A buy-in is recorded nowhere now**, so a buy-in promotion never pays and Sessions show time only: question #1009.
- **Before this reaches production:** count the rows of every dropped table there (read 15 Nov: every money table empty; seed rows only in chips, SOPs, quizzes and 25 membership cards), back up to `~/rivr-backups`, and check no control is in force.
