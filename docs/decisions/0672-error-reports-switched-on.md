# 0672 Error reports switched on: the player app on staging and production, with source maps

Date: 16 Nov 2026. The owner, 16 Nov: "Complete the sentry implementation" (#1004). Chosen: the player now, the other apps next (one more pull request); no Edge Functions; reports go straight to Sentry, with no relay on RIVR's domain (the owner's choice over a tunnel, knowing a browser or network that blocks Sentry then sends nothing). Builds on decision 0604, whose scrubbing and practice-venue silence are unchanged.

- **Two keys, one project.** The Sentry project `rivr-player` has a `production` key (100 reports an hour) and a `staging` key (30 an hour), so staging can never use up production's share. Each is the GitHub environment variable `SENTRY_DSN_PLAYER` of its environment, passed to the build as `VITE_SENTRY_DSN_PLAYER`: named for the app, as one build command builds every app. Release previews and pull requests get none, so e2e runs report nothing.
- **Labels.** `VITE_SENTRY_ENVIRONMENT` is `staging` or `production`; `VITE_APP_VERSION` is the commit on staging and the release tag on production.
- **Allowed domains.** The project takes reports only from `https://app.rivrpoker.com` and `https://rivr-player-staging.pages.dev`; one from anywhere else is dropped (proved 16 Nov from this machine).
- **Source maps.** In a build with `SENTRY_AUTH_TOKEN` (CI's staging and production builds only), `@sentry/vite-plugin` makes hidden maps, marks each script with the id its map is uploaded under, uploads them to Sentry and deletes them; Workbox makes no map of the service worker; and each workflow deletes any `.map` left before the Cloudflare upload, Storybook's included (it made public ones before). Any other build makes none. A failed upload is a warning, never a failed release. The token is given to the build step alone, not the job, so installs, Storybook and the deploy never see it, and the Sentry CLI inside the plugin sends nothing of its own (`SENTRY_CLI_NO_TELEMETRY`, set in the Vite config, as Turborepo hands a build only the variables `turbo.json` names). Turborepo passes it through to the build (`passThroughEnv`), outside the cache key: CI's runners keep no build cache, so no build is reused without its upload. Each environment has its own organisation token (`org:ci`), so either can be revoked alone. The scrubber now lets `debug_meta` through: each script's address (scrubbed as a frame's) and its map's id, nothing else.
- **Proved 16 Nov** with a local build on the staging key: the scripts carried their ids, no map was left, and a failed sign-in reached Sentry as `refused:unavailable` with its stack read back to `src/features/sign-in/components/PhoneStep.tsx` line 40, the right environment, release and tags, and none of the number typed.
- **Privacy notice.** It names Sentry, Functional Software in the United States, what a report holds (what failed, the screens and requests just before it, the browser), that phone numbers, PANs and other long numbers are removed (not "anything typed": a name in an error's own words can pass, decision 0604), and that Sentry notes the city it comes from (migration `20261122110000_website_privacy_names_sentry.sql`; a club's own words stay). Production's and staging's notices held the exact line it edits on 16 Nov; after a release, the privacy page should name Sentry.
- **Off switch.** Disable the key in Sentry (Settings, Client Keys): reports stop at once, with no deploy.
